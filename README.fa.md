# اصلاح نمایش ریز مطالبات

بسته اصلاحی برای نسخه main بررسی‌شده در ۵ اکتبر ۲۰۲۶. روی GitHub یا Vercel منتشر نشده و به دیتابیس واقعی متصل نشده است.

## امکانات

- ریز هر خودرو با نام، مدل، سال، رنگ، پلاک، تاریخ فروش و لینک پرونده
- خریدار، مبلغ دقیق فروش، دریافتی ثبت‌شده و مانده به تومان
- جست‌وجوی خودرو، پلاک، خریدار و شماره قولنامه با ارقام فارسی و عربی
- فیلتر همه، بدون دریافت ثبت‌شده و دریافت ناقص ثبت‌شده
- تعداد خودرو و جمع مانده فیلتر فعلی
- مبلغ و نزدیک‌ترین سررسید چک‌های دریافتی در انتظار، بدون کسر دوباره از مانده
- لینک مدیریت پرداخت قولنامه‌های امضاشده، به جای ثبت دریافت مستقل برای همان خودرو
- فرم دریافت درجا برای فروش بدون قولنامه امضاشده، با خودرو ثابت و خریدار از پیش پرشده

«دریافتی ثبت نشده» به معنای قطعی «خریدار پرداخت نکرده» نیست. اگر پول رسیده اما ثبت نشده، ابتدا رسید بانکی و سوابق را بررسی کنید، سپس فقط یک دریافت ثبت کنید. این بسته اتصال بانکی یا وضعیت تأییدشده عدم پرداخت اضافه نمی‌کند.

## نصب

۱. از سورس و دیتابیس پشتیبان بگیرید و روی شاخه آزمایشی کار کنید. ZIP را در پوشه جدا، مثلاً `receivables-patch`، استخراج کنید.

۲. از ریشه پروژه پیش‌نمایش بدون نوشتن را اجرا کنید:

```sh
python3 receivables-patch/install.py
```

۳. پس از بررسی، اعمال کنید:

```sh
python3 receivables-patch/install.py --apply
```

فقط این چهار فایل درگیرند:

```text
app/cashflow/page.js                 (ویرایش)
components/CashflowClient.jsx        (ویرایش)
components/ReceivablesPanel.jsx      (جدید)
lib/receivables.js                   (جدید)
```

اسکریپت نسخه دقیق دو فایل موجود را با هش Git مقایسه می‌کند و قبل از تغییر از آن‌ها پشتیبان می‌گیرد. اگر فایل‌ها متفاوت باشند، حتی در پایان خط، بدون تغییر متوقف می‌شود؛ ادغام دستی زیر را انجام دهید. پکیج جدید، تغییر مدل و مهاجرت دیتابیس لازم نیست.

۴. آزمون و build:

```sh
node --test receivables-patch/tests/receivables.test.mjs
python3 receivables-patch/tests/test_install.py
npm run build
```

۵. در دیتابیس آزمایشی فروش بدون دریافت، دریافت جزئی و کامل، چک در انتظار و وصول‌شده، قولنامه امضاشده، چند خودروی مشابه، نام و پلاک خالی، جست‌وجوی فارسی، خطای ذخیره، کیبورد و موبایل ۳۲۰/۳۹۰ پیکسل را بررسی کنید. فقط بعد از آزمون موفق commit/push و انتشار کنید.

## ادغام دستی

دو فایل جدید components/ReceivablesPanel.jsx و lib/receivables.js را به مسیر متناظر در پروژه کپی کنید.

در components/CashflowClient.jsx، import زیر و prop جدید `receivables = []` را اضافه کنید:

```jsx
import ReceivablesPanel from './ReceivablesPanel';
```

داخل cashflow-screen، پیش از بخش تراکنش‌ها:

```jsx
<ReceivablesPanel receivables={receivables} cars={cars} />
```

در app/cashflow/page.js، Contract را به import مدل‌ها اضافه کنید و:

```jsx
import { buildReceivableRows } from '@/lib/receivables';
```

پس از Promise.all موجود، پیش از return:

```jsx
const signedContracts = o.receivables.length
  ? plain(await Contract.find({
      car: { $in: o.receivables.map(c => c._id) }, status: 'signed'
    }).select('car number buyer.name status')
      .sort({ signedAt: -1, _id: -1 }).lean())
  : [];
const receivables = buildReceivableRows(o.receivables, signedContracts, plain(q));
```

prop جدید `receivables={receivables}` را به CashflowClient داخل return اضافه کنید؛ سایر props و منطق قبلی را نگه دارید.

## قواعد حسابداری و محدودیت‌ها

- مبنای مانده همان loadOverview فعلی است: قیمت فروش منهای ورودی با بابت sale و خودرو متصل. این بسته حسابداری را بازنویسی نمی‌کند.
- دریافت بدون خودرو یا با بابت دیگر در این محاسبه لحاظ نمی‌شود؛ قبل از ثبت مجدد سوابق را بررسی کنید.
- خودرو بدون قیمت فروش معتبر یا با وضعیت خارج از فروش ممکن است مثل قبل در فهرست نیاید.
- در قولنامه امضاشده پرداخت را از مدیریت قولنامه «دریافت شد / پاس شد» کنید؛ تراکنش دستی موازی نسازید. اگر چند قولنامه امضاشده باشند، همه لینک‌ها و هشدار نمایش داده می‌شوند و خودکار انتخاب نمی‌شوند.
- فرم فعلی پروژه امکان تغییر جهت و بابت دارد؛ برای کاهش مانده این مسیر، «ورودی» و «فروش» باید باقی بمانند. خودرو ثابت است. مبلغ عمداً صفر است تا فقط مبلغ واقعی دریافت‌شده وارد شود.
- چک در انتظار پول وصول‌شده نیست. مبلغ آن از مانده دوباره کم نمی‌شود. سررسید نمایش‌داده‌شده فقط سررسید چک در انتظار است، نه موعد کل بدهی.
- چک برگشتی، یادآور، ثبت وضعیت پیگیری مستقل و رسید بانکی جدید اضافه نشده‌اند.
- گزارش سود و برنامه پرداخت قولنامه ممکن است در سورس فعلی از منابع متفاوت استفاده کنند؛ این بسته آن‌ها را یکپارچه نمی‌کند.
- چاپ تراکنش‌ها دست‌نخورده است؛ چاپ اختصاصی ریز مطالبات اضافه نشده.
- build کامل Next.js، آزمون ذخیره واقعی و آزمون مرورگر واقعی در این محیط انجام نشده‌اند. نتیجه بررسی‌های اجراشده در TEST-RESULTS.fa.md است.

## بازگشت

دو فایل موجود را از پوشه `.receivables-backup-...` نصب برگردانید. دو فایل جدید را فقط اگر بعداً به آن‌ها وابستگی اضافه نکرده‌اید حذف کنید. دیتابیس تغییر نکرده است.
